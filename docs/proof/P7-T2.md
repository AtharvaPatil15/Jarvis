# Proof — P7-T2: `create_folder` tool

- Date: 2026-09-17 (local)
- Branch: testing
- Base commit before this task: `73e0efc`
- Reported by the owner while using the app: "when I told it to create a new folder in documents, it could not do it."

## Diagnosis
JARVIS's file tools were read-only: `search_files` and `read_file` (`assistant/tools/builtin/files.py`), registered in
`assistant/tools/builtin/__init__.py`. There was no tool that creates anything, so a request to make a folder had no
matching tool — this was a missing capability, not a bug in existing code (confirmed against `docs/plan/phase-5-actions.md`,
which only ever specified `search_files` and `read_file`).

## What changed
- `assistant/tools/builtin/files.py`: new `CreateFolderTool` (`create_folder`, `requires_permission = True`), sandboxed
  to `settings.file_roots` the same way `read_file` is.
- `assistant/tools/builtin/__init__.py`: registers `CreateFolderTool(settings.file_roots)`.
- `tests/unit/test_file_tools.py`: 4 new tests.
- `README.md`, `SECURITY.md`: tool list and permission table updated.
- `docs/DECISIONS.md`: D-028.
